# 数据备份格式与迁移

`src/lib/data-backup.ts` 中的 `BACKUP_VERSION` 是备份数据结构版本，当前为 `2`。
它与 `appVersion` 独立：应用发布新版本时，不必递增备份版本；备份结构发生变化时，必须递增备份版本并提供迁移。

## 当前格式

JSON 顶层包含 `type: "anitabi-backup"`、整数 `version`、`appVersion`、`exportedAt` 和 `data`。
点击“导出备份”后，在 Sheet 中勾选收藏、巡礼计划，默认两项均勾选，至少选择一项。
确认导出时先关闭 Sheet，再打开系统分享；取消或下滑关闭不会导出。
`data` 仅保存勾选类别的数据；未勾选类别的字段完全省略，不能用空数组代替。

- 收藏对应 `favoritePoints`。
- 巡礼计划对应 `plans` 和 `planListSortOrder`；两个字段必须同时存在或同时省略。

已勾选但没有数据的类别仍保存空数组，表示该类别的有效空备份。
计划保留 ID、名称、描述、时间、点位顺序、完成状态和信息快照，包括空计划。

`src/lib/data-backup-schema.ts` 显式定义 `DataBackupV1`、`DataBackupV2` 等文件格式类型。
这些历史类型必须保持不变，不能改为引用随应用演进的存储模型类型。
`BackupContents` 表示备份文件中实际包含的类别，`BackupData` 表示包含全部类别的本地状态。

例如，仅备份收藏时，`data` 为 `{ "favoritePoints": [...] }`；仅备份计划时，
`data` 为 `{ "plans": [...], "planListSortOrder": "desc" }`。

## 恢复流程

1. 读取 JSON，并检查文件大小、文件标识、元信息及版本是否有效。
2. 检查旧版本到当前版本的完整迁移路径。
3. 按 `1 → 2 → 3 …` 顺序迁移 `data`，保留文件原始 `appVersion` 和 `exportedAt`。
4. 严格校验迁移结果是否满足当前版本结构。
5. 展示文件实际包含的类别和恢复摘要，等待用户选择合并或覆盖，再写入存储。

恢复只处理文件中包含的类别，省略的类别不写存储、不发布到对应的状态仓库：

- 合并时按收藏点位 key、计划 ID 和计划内点位 key 去重，保留本地名称、描述、顺序和完成状态，仅追加新数据；计划列表排序偏好始终保留本地值。
- 覆盖时只替换包含的类别；仅恢复收藏不会改动计划，仅恢复计划不会改动收藏。包含计划时一并恢复其排序偏好。
- 包含某类别的空数组会在覆盖时清空该类别；省略该类别则保留原有数据。包含空计划备份时也会写入计划存储，防止重新生成首次安装示例计划。

所有需要的写入和回滚快照先准备完成，再同步写入存储；全部成功后才发布状态。
写入失败时回滚已尝试的步骤，包括发生异常的步骤，不发布成功状态。

迁移只发生在内存中，不修改原始文件和本地存储。
迁移函数会收到原数据的独立副本；迁移链缺失、函数抛出异常或结果无效时，恢复会在存储写入前停止。
更高版本的备份不会尝试降级；没有版本号的文件不会猜测版本。

## V1 兼容

V1 文件始终包含收藏、计划和计划列表排序偏好。导入时先按冻结的 V1 结构严格校验，
再通过 `1 → 2` 迁移为包含全部类别的 V2 数据，保留文件原始 `appVersion` 和 `exportedAt`。
缺少类别或其他结构错误的 V1 文件仍视为无效，不能按 V2 的局部备份解释。
迁移后的 V1 文件继续支持原有全量合并、全量覆盖；再次导出使用 V2 格式。
旧版应用不支持 V2 文件，需要升级后恢复。

## 新增结构版本

例如未来新增 V3 时：

1. 保留 V1、V2 类型，新增 `DataBackupV3` 及所需类型。
2. 把 `BACKUP_VERSION` 改为 `3`，将 `DataBackup` 指向 V3，并更新当前结构校验和导出逻辑。
3. 保留 `1 → 2`，在 `BACKUP_MIGRATIONS` 注册 `2: migrateV2ToV3`。注册表的键是来源版本，每个函数只迁移到下一个版本。
4. 迁移函数接收 `unknown`，应先按历史结构校验，再转换字段。旧格式没有的新字段需要明确定义默认值；不能丢弃完成状态、时间、顺序、快照或空计划。
5. 增加真实旧版文件测试：通过 `parseDataBackup` 迁移后，分别验证合并、覆盖和重新导出。

新增版本时继续保留历史迁移链，无需为每个旧版本重新编写直达最新版的迁移。

测试同时覆盖真实 V1 文件迁移、单类别备份与恢复、空已选类别、局部写入及失败回滚。
`migrateBackupData` 的独立测试使用模拟结构验证多步转换、路径缺失、未来版本拒绝、迁移失败及源数据保护；模拟结构不代表应用的实际文件格式。
