# 地图选中标记

## 图层与数据

首页选中圆点由 `SelectedMapPointLayer` 绘制。独立 `selected-map-point-source` 最多包含一个点，取消选中时为空；圆点样式复用普通圆点的原生缩放表达式。

计划地图使用 `SelectedPlanMapPointLayer`：通过 `Mapbox.Image` 将图片、圆角边框、当前点位标签和圆点生成为纹理，再用单个 `SymbolLayer` 绘制。纹理复用一个 ID，在选中内容、图片显示、主题、语言和图片开关变化时刷新。定位、旋转与缩放期间不再同步选中 `MarkerView` 的屏幕位置。点击由 `ShapeSource` 处理；不提供原 Pressable 的按压变淡反馈，点位操作仍可从计划卡片和列表进入。

选中照片与普通缩略图使用相同的 `h160` 地址，并使用 React Native `Image` 对齐 Mapbox 的原生图片加载管线。Android 通过 Fresco 复用缩略图缓存，关闭图片渐显及解码尺寸变换。

`Images` 与 `Mapbox.Image` 从地图首次挂载开始保持注册，地图未就绪时使用透明占位子视图；地图加载完成后才将子根替换为完整 artwork。Android 的 `RNMBXImage` 首次添加子视图时可能尚未拿到地图引用，而后续 `addToMap` 不会补挂该子视图；未挂到窗口的 Fresco 图片不会开始加载，所以仅反复刷新快照无法解决首入空框。提前注册父容器、在地图就绪后替换整个子根，确保照片挂入离屏视图。保留布局快照与 `onLoad` 后的完整照片刷新；设备验收同时覆盖首入、退出重入和连续切点。

首页巡礼点 PopupCard 和附近位置卡片包含图片、导航等交互，使用 `MarkerView`。关闭时卸载对应注解。首页普通点切换时复用一个注解，更新其坐标与卡片内容；附近位置使用点击序号创建独立注解，同一附近位置的行政区更新不会重新创建注解。

2026-11-11 在 Android 模拟器上试验复用首页普通点 `MarkerView`：两个不同位置切换时，录屏连续两帧在旧位置显示了新点名称和图片占位，随后才移到新位置。此结果只覆盖所测模拟器与切换场景；JS 的布局或帧回调不能证明 Mapbox 注解已在目标位置绘制完成。

曾试验短暂保留旧注解直至新注解布局后的双卡交接，近距离切换避免了中间露出底图，但录屏显示新卡出现后旧卡边缘仍短暂可见。根据单卡偏好改为复用单个注解；单卡方案无法保证内容与位置同帧提交，上述错位风险仍存在。

在 Android 模拟器以袋井站附近同一作品的两个相邻点、首页视野截图条和相机平移进行对比：单卡方案未发现整张卡片消失的帧，但切换时可观察到新名称和图片占位先于位置更新。这个结果仅覆盖所测设备和场景，不能保证其他设备、iOS 或不同地图负载下完全无闪。

附近卡片首次打开前先查询当前底图的已渲染地点，将地名、英文名和图标标识一次性写入状态后挂载，避免先显示坐标卡、随后新增名称行使底部锚定的卡片向上跳。未命中地点或查询失败时，首次点击仍显示坐标和附近巡礼点；已有卡片时，仅确认无地点名称才关闭，查询失败保留原卡片。查询期间的后续点击、选点、地图移动和样式变化会使旧结果失效。

首页和计划地图的附近候选都先排除没有截图路径或路径为空白的点，再按距离取最近 3 个；不使用作品封面为无截图点补位。不足 3 个时显示实际数量，没有带截图的候选时隐藏图片行。

计划地图复用同一附近地点识别与卡片 UI，但附近位置由计划页独立管理，不写入首页 `useMapBrowse`，也不替换计划已选点。打开、关闭或切换附近卡片时，底部计划卡与当前点标记保持原状；计划页的空白点击仅切换附近卡片：已开则关闭，未开则显示附近点和坐标。附近候选只来自当前计划成员并跟随计划页作品筛选，不使用首页筛选。点击附近截图走计划原有选点与相机流程，并关闭附近卡片；通过地图点选、列表、底卡切换到不同计划点时也关闭附近卡片，普通操作重新选中同一点、底卡重新定位及筛选作品仍保留附近卡。原有相机策略、完成状态与底部卡相机边距不变。已选 artwork 的命中优先级仍高于底图 POI，跨点查询与本地图标准备保留点击、选择、相机、样式和地图实例的失效保护。

两种模式共用 `SELECTED_MAP_POINT_LAYER_ID` 作为排序锚点。普通圆点、点位缩略图和番剧图标都设置 `belowLayerID`，保证选中标记高于这些图层。选中层始终挂载；新增 marker 图层时也要声明这一关系。该关系不代表选中标记高于 Popup 等原生视图。

附近卡片的底部箭头参与 `MarkerView` 尺寸计算，底部中心锚点落在箭头尖端。标题行至少保留 22 高。图标先按图集元数据的整数像素矩形裁出独立 PNG，再缩放显示，防止相邻图标像素渗入。名称优先使用实际图标主色，缺少主色时按当前 Mapbox 样式的标签图层、要素属性和 zoom 在 JS 中求值；未知表达式回退主题文字色。颜色相对实际卡片背景不足 4.5:1 时调整亮度，因此卫星白色标签在浅色卡片上不会直接使用白字。样式请求按样式去重并持久缓存，过期刷新失败保留旧数据；清除地图缓存也会使在途请求失效。

浏览地图提前预取图集与当前样式。命中地点后只用已有本地图集准备裁图、主色和已解码的 `ImageRef`，准备完成再一次性写入开卡状态；准备期间保留旧卡，后续点击或地图变化仍会使旧任务失效。卡片挂载后不再订阅图集更新，也不再用 `onLoad` 将备用图标和默认文字色替换成最终外观。无本地图集、缺少图标或准备失败时，本次卡片固定使用回退外观，后台下载只供下次打开使用，点击不等待网络。已解码图标缓存最多保留 64 项，淘汰时仅移除引用，不释放仍可能被可见卡片使用的图像。地图文字色同步读取缓存，并按地点、样式和 zoom 固定快照，后台缓存更新及行政区更新不会使已显示标题变色；显式切换地图样式或 zoom 时重新取样。

首页和计划地图的普通点位缩略图沿用“纬度越低越靠上”的顺序。同纬度点位按数据顺序决定上下层级。排序值在图片点位索引建立时生成一次；缩放、视口筛选和图片开关复用该结果。点位数据列表更新时重新建立索引。

番剧图标、普通圆点和首页选中圆点共用固定的 `MAP_MARKER_HITBOX = { width: 12, height: 12 }`，单位为 Android dp / iOS points。查询框以点击位置为中心，在标记可命中区域外提供约每侧 6 个逻辑像素的水平、垂直容错，并非将整个标记的点击区域限制为 12×12。固定逻辑单位让不同屏幕密度上的容错尺度一致，不再按屏幕密度换算来复刻旧版 Android 的物理像素范围。新版 Mapbox 默认 44×44 的查询容差对密集地图偏宽；直接归零则会降低小圆点的点击容错，因此采用 12×12。

点位缩略图保留升级前已有的 `hitbox={{ width: 0, height: 0 }}`；普通圆点由首页和计划地图共用，两处都使用固定的 12×12 容差，计划地图选中 artwork 的可见区域判断保持独立。点击仍按 Mapbox 的渲染要素规则拾取，番剧图标及文字都可命中，不提供图片逐像素透明度检测。

## 切换选中的更新范围

- 首页保留普通点位数据，仅更新单点源，普通圆点由相同样式的选中圆点覆盖。
- 计划地图保留普通圆点及缩略图数据，通过 `MapMarkerSelectionContext` 仅让绘制层更新透明度表达式，隐藏选中点的普通圆点、白边和缩略图。匹配使用番剧 ID 与点位 ID，避免不同作品中的同名 ID 相互影响。
- 普通数据源不订阅选中状态；缩略图的视口和密度筛选不依赖选中点。布局、来源数据或番剧筛选变化仍可触发必要的数据更新。
- 计划地图的普通圆点、缩略图和地图空白点击保持稳定事件回调。选中点、artwork key 和父回调由 `useLayoutEffect` 发布到 ref，事件读取最近一次已提交的数据，避免切点或父回调更新让 `ShapeSource` 再次序列化完整 GeoJSON；未提交的渲染不改变事件快照。异步屏幕投影期间换点、取消选中或切换图片开关时，旧 artwork 命中失效，仍按原逻辑回退到被点击的普通点。地图实例替换或卸载后丢弃旧地图的在途点击。
- 原有选中点查找、相机事件处理和原生样式求值仍有开销，不能将整个交互称为常数开销，也没有真机帧率对比结果。
- 未选中时使用空数据源，避免用恒假过滤表达式模拟空选中状态。

## 首页卡片切换时序研究（2026-11-12，未实施）

本次结论来自现有代码、Git 历史、已安装的 `@rnmapbox/maps 10.3.16` 源码和 Mapbox 官方资料。仅记录研究与候选设计，没有修改应用或第三方代码，没有创建或应用依赖补丁，也没有构建或新增设备验证。前文的录屏结果属于此前的 Android 模拟器试验，不能作为下面原生方案的验证结果。

用户当前决定先保留实现，将原生同步交接作为后续优化方向；尚未批准第三方补丁或构建。未来实施仍须分别遵守 [AGENTS.md](../../AGENTS.md) 的补丁与构建授权要求。

### 问题原因与历史

首页 [MapContainer](../../src/components/map/map-container.tsx) 在同一次 React 更新中，将新坐标传给复用的 `MarkerView`，将新点位数据传给 `PopupCard`。两者在原生端经过不同的更新流程：

- 内容由 React Native 更新到子视图。
- `coordinate` 是给 Mapbox 的地理定位请求，不是普通 View 的 `left`、`top` 或 `transform`。Android 的 `RNMBXMarkerView.setCoordinate()` 调用 `updateViewAnnotation()`，实际屏幕位置稍后由 Mapbox 更新。

因此，React 同批提交并不保证 Mapbox 定位和子视图内容在同一帧生效，可能出现“新内容仍在旧位置，随后卡片才移动”。单纯合并 state、改变 effect 类型或等待若干 JS 帧，不能消除这个跨流程的同步问题。

普通 React Native View 的位置和内容如果来自同一次提交，且没有独立的位置动画、effect 后续更新或异步资源加载，通常可以在下一次绘制中一起呈现。Fabric 会提交新视图树、计算布局并应用到原生视图；原生属性逐项修改不等于屏幕逐项绘制。这说明“位置与内容一起更新”是合理的目标，但不能把普通 View 的行为直接套到 Mapbox 注解上。参见 [React Native 渲染流程](https://reactnative.dev/architecture/render-pipeline) 和 [React 批量更新说明](https://react.dev/learn/queueing-a-series-of-state-updates)。

相关历史说明当前复用行为有明确意图，不能当作无意遗漏直接恢复 `key`：

| 提交 | 行为与意图 |
| --- | --- |
| `df6eabf` | 复用注解，切换时隐藏内容，等待一次原生地图调用和两次 `requestAnimationFrame` 回调后显示；等待本身不是注解已就位的确认。 |
| `770413c` | 按作品、点位与坐标重建注解，避免复用时内容和位置不同步。 |

| `bc77b74` | 避免重复选择同一截图时重新挂载卡片造成闪烁；后续优化仍须保留同点复选的实例与图片状态。 |

### 原生 API 已确认的能力与限制

**Android：** 项目依赖的默认 Mapbox Android SDK 为 `11.33.0`。其 `ViewAnnotationManagerImpl.positionAnnotationViews()` 先在主线程设置注解的 `translationX/Y`，再依次通知屏幕位置、锚点配置和锚点地理坐标变化。相关 API 是 `onViewAnnotationPositionUpdated` 和 `onViewAnnotationAnchorCoordinateUpdated`，但现有 React Native `MarkerView` 没有把它们开放给 JS。参见 [版本源码](https://github.com/mapbox/mapbox-maps-android/blob/v11.33.0/maps-sdk/src/main/java/com/mapbox/maps/viewannotation/ViewAnnotationManagerImpl.kt#L841-L954) 与 [监听器文档](https://docs.mapbox.com/android/maps/api/11.33.0/mapbox-maps-android/com.mapbox.maps.viewannotation/-on-view-annotation-updated-listener/)。

这些回调发生时，屏幕可能仍显示上一帧，这不意味着必须再等屏幕绘制后才能切换。可研究的切入点是在同一原生 UI 绘制周期内完成内容交接，使下一次绘制使用新的位置与内容，而不是把通知发回 JS 后再更新。这个判断来自源码顺序，尚未通过本项目设备验证，不能声称已保证零闪烁。

**iOS：** 本地 `RNMBXMarkerView` 使用 `ViewAnnotationManager` 的 add/update 接口。父注解视图的 `frame` 变化会调用内部 `onPositionChange`，Fabric 用它修正测量坐标，并非 JS 可订阅的定位完成事件。卡片尺寸调整也会改变 `frame`，该回调没有携带已采用的目标地理坐标或请求版本，不能直接视为对应切点请求完成。研究时没有完成项目所用 iOS SDK 的等效交接机制验证，不能把 Android 的回调方案直接照搬到 iOS。

以下机制均不能单独充当本次切换的完成信号：

- `onLayout` 主要反映 React Native 布局；`getPointInView()` 计算目标的投影位置，不证明注解已经移动到该位置。
- 当前封装对 Fabric 测量坐标做了修正，实际视图测量比固定延时更有依据，但测量、地图投影和相机变化之间仍可能发生竞态。
- 地图渲染帧回调不对应某个指定注解的切换请求；固定 `requestAnimationFrame` 次数也不是确认机制。
- `ViewAnnotationUpdateMode.MAP_SYNCHRONIZED` 面向注解与地图相机的同步，不提供 React 内容与注解坐标的共同提交。参见 [官方说明](https://docs.mapbox.com/android/maps/api/11.33.0/mapbox-maps-android/com.mapbox.maps.viewannotation/-view-annotation-update-mode/)。

### 候选方案：单注解的原生内容交接

目标是从“旧位置、旧尺寸、旧内容”直接呈现为“新位置、新尺寸、新内容”，继续保留卡片交互和原生地图跟随。切换期间不希望出现旧位置的新内容、中间空白或两张卡片同时可见；这些是验收目标，不是已实现的保证。

候选实现使用一个 Mapbox annotation，由原生宿主管理 active/pending 两份内容。双缓冲指内容视图，不是同时创建两个地图注解；核心是控制位置、尺寸与内容的共同绘制时机，双缓冲只是实现手段之一。

1. 保留 active 内容及其布局，准备 pending 内容。pending 允许布局测量，但不可见、不可点击，也不参与无障碍访问；其测量不能提前改变 active 的外框或底部锚点。
2. 新内容完成原生提交和测量后，按同一请求提交目标地理坐标、宽高和锚点参数。仅收到 React props 或 JS `onLayout`，不足以证明全部原生内容已准备好。
3. 原生核对对应注解实际采用的位置与尺寸，在可控的 UI 绘制时机切换 active/pending，避免再经过一次 JS 往返。之后通知 JS 已交接，用于释放旧内容、更新布局缓存等；JS 确认事件不负责决定本帧何时显示。
4. 重复选择同一点不重新挂载图片，也不无条件启动交接；同点的内容或尺寸变化仍需正常处理。快速切点、关闭或卸载使过期请求失效，最终显示最新选择。

实施前必须解决以下边界：

- **尺寸所有权：** 卡片高度随截图、简介、标题和来源变化。原生宿主必须协调实际内容布局和 Mapbox 注解尺寸；否则可能提前改变旧卡片大小，或新内容显示后再次触发锚点移动。不能只在现有 marker 中叠放两个普通 View。
- **请求一致性：** 请求需包含递增版本、点位身份、目标坐标、内容版本和尺寸。Mapbox 的位置、锚点坐标回调不是带完整请求标识的事务回执，不能把不同回调中的最近坐标和最近尺寸直接拼成一个已完成请求。需要验证快速 A→B→C、A→B→A、迟到内容提交及旧位置通知的处理。
- **没有变化事件：** Android 的相关通知只在对应位置、尺寸或锚点坐标改变时触发。同坐标、同尺寸以及被合并的更新可能没有新的通知；离屏或地图尚未就绪也不能假设会收到通知。需要明确的状态处理，不能超时后盲目显示。
- **可见性与生命周期：** 不应通过隐藏整条 Mapbox annotation 来准备布局，否则它可能退出布局计算。相机运动、样式切换、视口变化、失焦、关闭、地图替换和卸载均要使不再适用的请求失效，并清理监听器。
- **交互与现有流程：** 保留卡片按钮、图片预览、卡上拖动、底图防点穿和 Fabric 屏幕坐标测量；保持同点复选、布局补测和首页控件避障语义。旧 slot 的布局或图片回调不得写入新选择的状态，布局与避障逻辑必须核对事件所属点位和请求。
- **资源成本：** 两份内容会暂时增加视图、图片和订阅开销，需要控制缓冲数量和释放时机；不能将方案直接称为无成本的单卡复用。

### 讨论过的替代路径

| 路径 | 取舍与当前结论 |
| --- | --- |
| 按点位 `key` 重建 `MarkerView` | 避开旧注解承载新内容，但可能短暂露出底图并重新加载图片，改变现有复用意图；本次未采用。 |
| JS 延时隐藏、等待若干帧 | 可以遮住部分错位，但缺少目标就位依据，且引入消失阶段；本次未采用。 |
| 先移动，再更新内容 | 可以改变可见的先后顺序，但可能显示“旧内容先到新位置”，且需处理新内容高度变化；用户未选择此方案。 |
| 普通 RN 浮层 | 可把卡片内容和投影后的屏幕位置放入同一次 React 更新；地图运动时仍需异步投影，可能跟随滞后，手势、裁切和点击行为也会变化；用户对此不满意。 |
| 项目自有原生注解组件 | 可避免第三方补丁，但需要自行接入地图生命周期，处理 Fabric 坐标测量、点击拦截、子视图挂载和尺寸所有权；不是简单增加一个 Expo View，用户对此不满意。 |
| 扩展现有 `MarkerView` 原生实现 | 更容易保留已有的测量、触摸和地图集成，是后续优先研究方向；需要明确批准依赖补丁，并分别适配、验证 Android/iOS。当前尚未实施。 |

`PointAnnotation` 在 Android 上会将子内容位图化，也不适合直接替换具有多个操作按钮和图片预览的卡片。

### 后续验证范围

轻量测试可覆盖请求状态机、过期回调、同点复选、关闭和布局避障的关联，不能证明原生绘制同帧。经单独批准进行原生构建后，需要在 Android/iOS 设备录屏逐帧检查：近距离与远距离切换、不同高度卡片、同坐标点、快速连续切点、慢图和无图、离屏与重入、相机平移/缩放/旋转/倾斜、样式切换以及关闭/重开。

验收同时检查是否出现旧位置的新内容、旧内容短暂落在新位置、空白帧、双卡残留和高度跳变，并复测按钮命中、图片预览、地图拖动、防点穿和无障碍访问。只有源码分析或状态机测试通过，不能宣称切换已无闪烁或性能已经改善。
