# 巡礼记录 MVP：需求与技术方案

更新日期：2026-10-29。

状态：首版 MVP 已接入代码，已完成一轮 Android 开发包真机验收。本文汇总已确认需求、当前实现方案与验证边界；iOS、大图压力和存储异常场景仍待验证。

## 1. 目标与核心概念

补上巡礼后的记录与回顾：用户沿用现有的计划勾选、对比拍摄和导出操作，自动留下按点位、日期组织的巡礼记录，并能查看、删除和备份这些记录及成品图片。

记录分为三层：

| 层级         | 含义                                             |
| ------------ | ------------------------------------------------ |
| 点位档案     | 一个巡礼点位的全部记录，独立于任何巡礼计划       |
| 每日巡礼记录 | 这个点位在某个本地自然日的一条记录，可以没有照片 |
| 成品照片     | 当次成功导出的成品图片，一条每日记录可以关联多张 |

同一点位同一天的多次实际到访合并为一条每日记录。若界面展示“巡礼次数”，其含义是有记录的天数，不是精确的现场到访次数。

## 2. 已确认的 MVP 需求

### 2.1 记录与计划 check 的关系

计划 check 继续表示该计划内点位的完成状态，各计划保持现有的独立逻辑。记录模块不维护全局“已去过”状态，也不保存 `check` 或 `planId`。

记录只接收用户勾选完成时产生的操作事件：

- 用户将一个点位从未完成勾选为完成时，创建或复用这个点位当天的巡礼记录。
- 取消勾选不生成记录，也不删除已有记录和照片。
- 导出图片只创建、追加巡礼记录，不修改任何计划的 check。
- 删除、恢复巡礼记录不修改计划的 check。
- 不同计划包含同一点位时，共用这个点位的巡礼记录和照片，但不因此同步 check。

### 2.2 生成时机与自动归档

| 用户操作或事件                   | 巡礼记录行为                         | 计划 check 行为        |
| -------------------------------- | ------------------------------------ | ---------------------- |
| 手动从未完成勾选为完成           | 创建或复用当天记录，允许没有照片     | 按现有逻辑更新当前计划 |
| 取消勾选                         | 保留记录和照片，不新增记录           | 按现有逻辑更新当前计划 |
| 对比成品成功保存到系统相册       | 创建或复用当天记录，追加当次成品图片 | 不修改                 |
| 同一天再次拍摄并成功导出         | 向当天记录追加图片                   | 不修改                 |
| 同一次拍摄修改配置后再次成功导出 | 每张成品分别保留，归入操作当天的记录 | 不修改                 |
| 另一天再次成功导出               | 创建或复用那一天的记录               | 不修改                 |
| 仅拍照、打开结果页、调整导出配置 | 不生成记录                           | 不修改                 |
| 成品未能成功保存到系统相册       | 不因这次导出新增记录或照片           | 不修改                 |

“保存到系统相册成功”是导出生成记录的条件，不能仅因合成临时图片成功就生成记录。专用相册分类等具体异常边界见技术方案。

用户无需选择“加入已有巡礼”或“新建一次巡礼”，不增加导出归属选择步骤。归档仅由点位和操作时的本地日期决定。

### 2.3 日期与时间

- 同一个点位、同一个本地自然日只保留一条每日记录。
- 巡礼时间取当天记录首次生成时的时间，可能来自手动勾选，也可能来自首次成功导出。
- 当天后续勾选、追加照片不覆盖首次记录时间。
- 归档依据生成操作的时间，不使用照片 EXIF、结果页页脚的拍摄时间或系统相册时间重新决定归属。
- 同一天多个计划中的勾选事件仍复用同一点位的当天记录。

### 2.4 旧数据

不扫描现有计划完成状态、不迁移 check、不补建历史巡礼记录，也不扫描系统相册补录旧照片。

只有功能启用后重新发生已确认的勾选完成、成品成功保存事件，才创建或追加记录。启动应用、加载计划、导入计划、恢复旧备份均不视为用户重新勾选。

### 2.5 入口与查看

MVP 只提供“我的 → 巡礼记录”入口，放在现有“巡礼”分组中。

- 总览按点位列表展示，按最近巡礼时间倒序排列。
- 点击点位后，按日期倒序查看历史记录和照片。
- 没有照片的每日记录也要展示，不能因没有图片而丢失勾选留下的历史。
- 支持按番剧、时间段筛选，两种条件可以组合使用；总览顶部两个筛选按钮无背景、按内容宽度排列，清除筛选与按钮保持同一行。有条件时显示单个番剧名或已选番剧数量、快捷时间或自定义日期范围。
- 点击按钮打开对应的底部选择面板，统一使用“重置”“确定”：重置只清空当前面板的草稿，确定后才应用；下滑关闭、点关闭或返回均放弃未确定的改动。
- 番剧使用可搜索的多选列表，沿用计划选择器的右侧方框勾选样式，提供“全部番剧”以取消番剧限制；多个番剧取并集，再与时间条件组合。时间提供全部时间、最近7天、最近30天、本月、今年和自定义时间。两个面板均以有限高度打开，快捷时间下方不重复展示具体日期，自定义时才展示日期与日历。
- 自定义时间通过日历依次选择起止日期，支持跨月及快速切换年月，无需手动输入；允许同一天，范围包含起止当天。
- 有筛选时提供“清除筛选”以同时清空两个条件；没有匹配结果时仍保留筛选入口和清除操作。
- 从总览进入详情时沿用日期范围，用户可清除范围查看全部历史；从详情返回时保留总览筛选。
- 删除全部每日记录后，该点位不再作为有记录的点位出现在总览中；其计划 check 保持原样。

首版总览显示番剧名、点位名、最近日期、记录天数、照片数和成品缩略图。详情按日期显示无图记录或三列照片，照片全屏查看复用现有图片预览能力。布局和手势仍需设备验收。

### 2.6 删除

详情右上角编辑图标直接进入删除模式，图标不带文字，无障碍标签为“编辑”，不立即弹出确认框。常态不显示日期或照片上的垃圾桶，点击缩略图仍打开原有大图预览。页面不展示删除规则提示，范围说明保留在删除确认弹窗中。进入模式后，顶部提供“取消”；点取消或系统返回只退出模式并清空勾选，不离开详情页。

删除模式支持跨日期勾选照片、勾选整天记录，以及全选当前可见日期。保留三种删除范围：

1. 仅勾选照片：删除这些照片的元数据与应用内副本，保留当天记录、首次巡礼时间及其他照片。即使逐张选完当天所有照片，也不会自动升级为删除当天记录；删除最后一张后显示当天无图记录。
2. 勾选日期：删除该天的巡礼记录及其全部应用内照片，无图日期也可以勾选。整天选择覆盖其照片，不重复计数；选中整天后取消其中一张照片，会取消整天删除，改为仅选择其余照片。
3. 全选：选择当前可见日期的整天记录及其照片；未筛选时可删除该点位全部记录。有日期筛选时只选择当前展示的日期，不包含筛选之外的历史。

底部操作栏使用正常布局固定在列表之外，提供全选或取消全选、已选记录天数和照片数、删除所选。照片计数包含所选日期下的照片和单独勾选的照片，并去除重复。未选内容时不能删除；点删除所选后统一确认范围和数量。取消确认保留勾选；删除期间禁用选择、预览和退出操作。删除成功后退出模式并清空选择；元数据写入失败时保留模式和选择，便于重试；元数据已删除但部分应用内文件未清理时提示清理失败，仍退出模式。

三种删除均保留所有计划的 check，不影响系统相册中的照片。删除后再次发生勾选完成或成功导出事件，仍按当天归档规则创建记录。照片按稳定 ID 选择和删除，不使用图片位置索引；只清理应用自己的记录和图片。

### 2.7 图片保存

应用自己保留一份导出成品图片，使用应用文档目录中的独立文件夹保存，不只引用系统相册资源。

- 记录查看使用应用自己的图片文件。
- 删除记录只清理应用自己的记录和图片。
- 成品副本属于用户数据，不属于可随“清除缓存”删除的缓存。
- MVP 保存导出的成品，不额外保存相机原始照片、参考图副本或可恢复的编辑草稿。

### 2.8 备份与恢复

现有备份入口需要支持“巡礼记录（含照片）”，作为与收藏、巡礼计划并列的独立类别。

- 备份必须包含记录元数据和实际成品图片文件，不能只有当前设备的图片路径。
- 恢复记录及其图片到应用自己的存储，不重复写入系统相册。
- 巡礼记录恢复不修改计划 check；备份中若同时包含计划，计划完成状态按原有计划恢复逻辑处理。
- 数据恢复不走勾选、导出等业务事件，不生成恢复当天的额外巡礼记录。
- 保留原记录日期、首次记录时间和照片身份，不把恢复时间当作巡礼时间。

## 3. 技术方案

### 3.1 当前代码基础

接入点如下：

- [计划状态](../../src/store/use-plans.ts) 使用 Zustand，`togglePoint(planId, itemKey)` 切换指定计划内状态，仅在用户勾选为完成时调用记录服务。
- [计划存储](../../src/lib/plan-storage.ts) 使用 MMKV，`completed` 属于 `PlanItem`。
- [相机入口](../../src/components/comparison-camera/comparison-camera-button.tsx) 已携带番剧和点位信息，无需为记录增加来源计划参数。
- [结果保存](../../src/components/comparison-camera/comparison-result-modal.tsx) 在 `MediaLibrary.Asset.create` 成功后调用记录服务保存应用成品副本，之后才清理导出临时文件；不调用计划 check。
- [清除缓存](../../src/lib/app-cache.ts) 当前单独清理地图、番剧图标和图片缓存，新记录图片目录应继续独立管理。
- [备份格式](../data-backup.md) 已扩展为 V3，包含巡礼记录时使用 ZIP 保存图片；V1/V2 JSON 继续兼容。

### 3.2 存储职责与模型

沿用 Zustand、MMKV 和 Expo FileSystem，不为 MVP 引入新的数据库或后端。

| 部分     | 拟保存信息或职责                                             |
| -------- | ------------------------------------------------------------ |
| 点位档案 | `pointKey`、`bangumiId`、`pointId`、番剧和点位名称等快照     |
| 每日记录 | `dateKey`、`firstRecordedAt`、照片列表                       |
| 成品照片 | 稳定的 `photoId`、应用内相对文件路径、宽高                   |
| Zustand  | 提供记录状态、查询和界面更新                                 |
| MMKV     | 持久化记录元数据，建议按点位分别保存，避免每次追加都重写全库 |
| 文件服务 | 管理成品文件的保存、读取、删除和备份恢复                     |

点位身份沿用现有的 `${bangumiId}:${pointId}`，同一地理位置下不同的上游点位不按坐标自动合并。

`dateKey` 在记录创建时保存为本地日期 `YYYY-MM-DD`，随后直接使用这个已保存的归档日期，不随手机时区变化重新计算历史分组。`firstRecordedAt` 保存时间戳，追加图片时保持不变。

图片保存相对文件路径，读取时基于当前 `Paths.document` 还原 URI。系统相册资源 ID 不作为记录身份或恢复到另一台设备后的图片来源。

模型中不加入全局 `visited`、check 或来源计划字段。当前实现分为 [纯模型](../../src/lib/pilgrimage-records.ts)、[MMKV 存储](../../src/lib/pilgrimage-record-storage.ts)、[文件管理](../../src/lib/pilgrimage-record-files.ts)、[状态仓库](../../src/store/use-pilgrimage-records.ts) 与 [记录服务](../../src/services/pilgrimage-records.ts)。

普通事件只序列化、写入发生变化的点位。读取异常时保留原始数据、显示失败状态并阻止普通写入；允许用户通过明确的覆盖恢复修复。写入与回滚均失败时，也关闭后续普通写入，避免继续覆盖不确定的数据。

#### 本地结构版本与迁移

本地版本独立于应用版本和备份版本，当前为 `1`。`schema-version` 保存严格的正整数版本字符串；历史无标记数据仅在该键确实不存在时按 V1 读取。现有 `point-v1:<编码后的点位 key>` 和记录字段不变，读取不会重写历史数据，首次实际修改才补写版本标记，无变化的重复打卡仍不写存储。

[本地格式](../../src/lib/pilgrimage-record-schema.ts) 冻结 V1 类型和运行时校验，并通过显式适配边界与应用模型转换。未来增加本地 V2 时，保留 V1 校验、新增逐版本迁移及当前格式适配器，再递增本地版本。迁移先确认完整路径，在独立副本上转换，每步按历史格式校验输入，最终按目标格式校验；不能通过当前应用模型猜测旧数据，不能重新计算历史日期、首次时间或照片身份。

[存储核心](../../src/lib/pilgrimage-record-storage-core.ts) 按版本分别保存点位。迁移完整写入并验证目标 `point-vN:` 命名空间、删除该目标区域上次未提交的多余记录后，最后更新 `schema-version` 指针；源版本始终保留原始字节。进程若在切换前终止，下次仍读取源版本并重新迁移；切换后读取完整目标。写入抛错可能发生在存储已经改变之后，因此迁移失败保留两套数据并关闭本次写入，不盲目删除目标或退回旧指针。

非法版本、超出当前程序能力的版本或点位命名空间会阻止普通写入和覆盖恢复，空库同样检查。当前受支持版本的损坏记录仍允许明确覆盖修复；覆盖与回滚一并处理版本标记及其原先缺省状态，普通修改仍只处理变更点位。已保留的旧命名空间只用于迁移提交保护：后续删除照片可能使旧引用失效，不能作为永久备份，也不在当前版本损坏时自动回退，避免复活已删除记录。

上述迁移提交保护针对元数据和应用进程中断，不扩展为图片与元数据的跨存储事务，也不承诺底层存储损坏或断电时的绝对持久性。当前仍为 V1，本次只建立版本和迁移边界，不改变已有记录的业务语义。

### 3.3 业务动作接入

记录服务提供“确保当天记录存在”“追加成功导出的照片”“删除单张照片”“删除单日”“删除点位全部”和“批量删除所选”等明确动作，文件 I/O 和持久化由服务统一协调。

计划按钮仍执行现有计划状态切换，仅在用户主动将状态变为完成时调用记录服务。不能用订阅 `completed` 变化的 effect 生成记录，否则启动、恢复和导入可能制造虚假的新记录。

相机成功导出使用单独的记录写入入口，不调用计划的 `togglePoint`。普通图片预览里的“保存到相册”也不当作一次新的对比拍摄导出。

追加、删除、照片备份和恢复通过记录服务的串行队列协调，避免较晚完成的文件操作覆盖更新后的记录，不引入额外的用户归属选择。

批量删除接收显式选择的日期和稳定照片 ID，在同一次串行操作中归一化范围：整天选择覆盖其照片，单独选中的照片只移除照片，不删除其日期记录。根据队列执行时的当前数据一次提交元数据，提交成功后再清理对应的应用图片，不通过循环调用单日或单张删除产生分批提交。元数据提交失败时不清理文件；文件清理失败沿用“内容已从记录移除，部分应用文件未清理”的错误边界，不把整批误报为尚未删除。元数据和文件不构成跨存储持久事务。

### 3.4 成品保存与失败边界

使用独立目录 `Paths.document/pilgrimage-records/images/`。图片使用唯一文件名，稳定照片 ID 与设备相对路径分别保存；正式元数据不引用即将清理的导出临时文件。

首版流程是：

1. 生成导出临时成品。
2. 将成品保存到系统相册。
3. 相册保存成功后，复制成品到应用文档目录，再提交当天记录和照片元数据。沿用现有分类失败边界：归入专用“Anitabi”相册失败不否定已经成功的系统相册保存，也不阻止记录写入。
4. 最后清理导出临时文件，不清理已被记录引用的正式副本。

应用副本、系统相册和 MMKV 不是一个跨存储事务，不能声称它们必定同时成功。错误处理需要区分：

- 相册尚未成功：不新增本次导出的记录或照片，清理本次准备的无引用副本。
- 相册已成功但记录写入失败：明确提示“已保存到相册，巡礼记录保存失败”，不将其笼统报告为导出保存失败，也不自动重复保存系统相册。
- 计划勾选成功但记录写入失败：分别说明计划操作和记录写入的结果，不把两者误报为同时成功。

应用副本或记录保存失败时，已经保存的系统相册成品保持原样，并提示部分失败。首版不增加仅重试记录的操作。记录元数据已删除但应用图片清理失败时，单独提示清理失败，不把它误报为记录仍未删除。

### 3.5 查询与界面

点位总览以有每日记录的档案为数据源，不读取 check 来决定是否显示。最近巡礼时间从记录中计算，不因照片追加的文件修改时间而改变已有每日记录的巡礼时间。

番剧筛选使用番剧 ID 数组，空数组表示不限制番剧，多个 ID 取并集；时间段筛选使用保存的巡礼日期和时间，与番剧条件取交集。手动勾选生成的无图记录与有图记录采用相同的筛选规则。

总览顶部以“全部番剧”“全部时间”两个无背景、按内容宽度排列的按钮承载筛选，“清除筛选”与它们保持同一行，长文字收缩截断。番剧面板支持名称搜索和多选，搜索不会丢失隐藏候选的已选状态；勾选使用项目已有的右侧方框样式。未选具体番剧时为全部，选一部时显示名称，选多部时显示数量。时间面板先提供快捷范围，快捷项下方不显示具体起止日，选择自定义后展示日历区间选择，支持跨月、月份跳转和年份网格。年份网格可按12年切换，便于查找较早的巡礼记录。

筛选面板统一使用项目已有的 TrueSheet：番剧约半屏并支持列表滚动；日期采用官方 `['peek', 'auto']` 两个内容档位，`TrueSheetPeek` 标记快捷选项区域，短档按标题、快捷选项和操作栏的实际尺寸计算，不为日历预留可见空白。日历始终挂载在 Peek 之后，完整档按全部内容自然撑开。选择自定义调用 `resize(1)`，选择快捷项或重置调用 `resize(0)`；已应用自定义条件时重新打开直接进入完整档。拖拽只改变展开程度，折叠保留自定义草稿和确认完整性校验；从快捷项手势展开后，首次选择日历日期才切换为自定义。标题及搜索使用固定 header，两个面板均使用固定 footer；正文末尾避让操作栏实测高度，日期的避让空间位于 Peek 外，避免短档重复计算操作栏高度。日期不设置 scrollable、GestureHandlerRootView 或伸展容器。

日期遮罩从短档开始变暗，阈值不随日历或年月视图高度改变。此前单一 `auto` 档在 Android 展开日历时，会按新的目标高度和尚未到位的位置重新计算遮罩透明度，产生短暂变亮；Peek 使用真实的快捷内容作为稳定阈值，不增加依赖补丁、自定义遮罩或固定高度。键盘处理沿用 TrueSheet 的原生行为。折叠后的日历关闭触摸与无障碍访问；完整的读屏操作仍需设备验收。面板与主列表保持 React 兄弟关系，只将按钮栏传入列表 Header，避免原生浮层仍继承外层滚动上下文而导致虚拟列表嵌套。参考：[TrueSheet Peeking Content](https://sheet.lodev09.com/guides/peeking)、[Dimming the Background](https://sheet.lodev09.com/guides/dimming)。

“最近7天”“最近30天”均包含今天；“本月”从本月1日起、“今年”从1月1日起，均截止今天。自定义起止日均包含在内，允许起止为同一天，不能在仅选一侧时确认。日期归档和范围摘要继续使用 `YYYY-MM-DD`，日历月份、星期及提示文案按当前应用语言展示。

自定义日历的区间展示参考 Wix Calendar 的 period marking 和 React DayPicker：起止日期使用主题色标记，中间日期以连续浅色背景连接，同日范围只显示单个标记。日历外上方不再展示起止摘要、选择提示或天数说明；“今天”定位按钮放在日历内部的顶部导航中，只定位当前月份，不改变草稿。顶部按钮不设置固定高度，保留适当横向内边距。点击邻月的补位日期时跟随切换月份；年月选择保留快速跳转并显示展开状态，日视图保留固定六周，避免切月时高度跳动。日单元格保留 44px 点击高度和按压反馈，选中标记宽度随窄列收缩；读屏标签包含本地化完整日期、今天及起止标识。参考：[Wix Calendar](https://wix.github.io/react-native-calendars/docs/Components/Calendar#date-marking)、[React DayPicker](https://daypicker.dev/docs/navigation#today-button)。

面板打开时从已应用条件建立草稿。“重置”只重置当前面板草稿；“确定”提交当前条件，下滑关闭、点关闭和返回只放弃草稿。列表的“清除筛选”同时清空番剧和时间。筛选后的排序、数量、缩略图使用命中日期的记录；进入详情时沿用日期范围，用户可清除范围查看该点位的全部历史；返回总览时保留原条件。无匹配结果也保留筛选和清除入口。

筛选面板从开始打开到关闭动画结束期间拦截系统返回和页面移除，返回只取消当前草稿并关闭面板。打开尚未完成时直接取消挂载，避免原生 dismiss 尚不可用而留下待打开的面板；已打开时先动画关闭，结束后才释放返回保护，随后返回可以正常离开巡礼记录页。

日期面板通过挂载后的 `ref.present(index)` 打开，初始索引固定为本次会话打开时的条件，后续草稿或父级已应用条件更新不会再次打开。使用库内部等待原生正文挂载的流程，避免 `initialDetentIndex` 在宿主 attach 时就自动展开，与 auto 首次测量竞争而偶发缺少遮罩。番剧的固定高度面板保留原有打开方式。取消仍销毁当前会话草稿；打开请求失败时关闭当前面板，旧会话取消后的异步失败不会影响后来打开的面板。不增加延时或重试；`resize` 仅用于用户主动选择快捷或自定义档位。

列表只在需要时加载照片和点位历史，使用虚拟列表与稳定的点位、照片身份。全屏图片展示优先接入已有预览组件，保留现有缩放、翻页和关闭交互。

### 3.6 备份格式与合并

当前实现采用以下封装和恢复规则，具体实现与验证说明见 [数据备份格式与迁移](../data-backup.md)。

新增 V3 数据结构，保持 V1/V2 类型不变。选中巡礼记录时导出 ZIP，内部包含元数据和实际图片，例如：

```text
backup.zip
├─ data.json
└─ images/
   ├─ <photoId>.jpg
   └─ ...
```

- 在现有导出选择中增加“巡礼记录（含照片）”。
- 元数据记录实际包含的类别，未选择的类别省略；不能用空数组代替未选择。
- 图片按文件打包，不使用 Base64 嵌入 JSON。
- 使用逐文件、分块读写，避免一次加载全部图片后同步打包。
- 继续识别 V1/V2 JSON。迁移后的旧备份省略巡礼记录类别，不能自动补成空数组，以免覆盖恢复时清空现有记录。
- 新格式的元数据大小限制和图片包大小限制分别处理，不能直接沿用当前 JSON 的 20 MiB 限制作为全部照片容量上限。

恢复规则：

| 恢复方式                     | 巡礼记录行为                                                         |
| ---------------------------- | -------------------------------------------------------------------- |
| 合并                         | 按点位和日期合并日记录；照片按稳定 ID 去重；同日首次记录时间取较早值 |
| 覆盖                         | 替换备份实际包含的巡礼记录类别及其应用内图片                         |
| 未包含巡礼记录类别           | 保留现有记录和照片，不写该类别                                       |
| 包含空巡礼记录类别并选择覆盖 | 清空应用内巡礼记录及其照片，不影响计划或系统相册                     |

照片 ID 在首次导出时生成，备份、恢复时保持稳定。两次独立成功导出的成品拥有不同 ID，即使内容相同也分别保留；重复恢复同一份备份不重复追加相同 ID 的照片。

恢复时先将图片解包、校验到暂存位置，准备正式文件，再提交元数据并发布状态。旧图片保留到新数据提交成功后再清理，避免先删除旧图导致失败时无法恢复。

现有 [恢复逻辑](../../src/lib/restore-data-backup.ts) 的写入回滚需要扩展到异步图片处理；当前同步 MMKV 回滚不能直接保证应用被终止时的跨文件一致性。

仅收藏或计划的新备份继续使用 JSON。首版 ZIP 使用 STORE 模式，并只接受该模式，避免同步解压造成大块输出分配。元数据上限 20 MiB，归档及解包总量上限 2 GiB，单张照片上限 128 MiB，归档最多 10000 个文件项；导入检查路径、文件清单、大小和 CRC。

备份页默认选择收藏、计划、巡礼记录三项，显示记录及照片数量、照片估算容量和打包/读取/恢复进度。处理期间阻止返回离开，避免提前清理正在使用的暂存图片；结束后恢复正常导航。覆盖继续使用原有的二次确认。收藏、计划和巡礼记录的备份与恢复均面向 Android/iOS 应用，Web 不在支持范围内。

## 5. 后续验证与限制

2026-10-29 使用 Xiaomi 25060RK16C（Android 16 / API 36）上的既有开发包，通过 Metro 加载当前代码，完成以下真机验证；本轮没有原生构建或安装新 APK：

- 实际相机以 2x 拍摄并保存，系统相册和应用内副本均成功生成，未改变计划；结果页保持相机停止，重拍保留 2x 变焦。
- 同日访问复用无图记录并保留首次时间；跨日保存照片；自定义日期筛选后全选删除只影响可见日期，取消确认保留数据和选择。
- V1 收藏与计划恢复、V2 仅计划类别的空数组覆盖、V3 照片 ZIP 合并与覆盖恢复；旧备份不补录巡礼记录，重复合并不产生重复照片。
- 清缓存及强制停止后冷启动，记录、照片文件、收藏和计划状态保留。
- 从应用导出包含 3 张照片、约 1.38 MB 的 ZIP，打开 Android 分享面板；经系统文件选择器选回该文件并完成合并恢复，数据未增加重复项。

真机发现筛选确认和批量删除按钮从禁用恢复后，原生可访问性状态仍可能保持禁用。共用 `StrictButton` 现显式同步 `accessibilityState.disabled`，保留其他可访问性标记和原有点击边界逻辑；相关操作已在设备上复验，并补充状态切换测试。本轮测试数据和系统相册测试图片已清理，开发包原有收藏、计划及记录经比对保持一致。

以下仍需设备验证，或属于后续完善范围：

1. iOS 全流程及原生发布包；Android 拒绝权限、权限撤销和存储写入失败的设备表现。
2. 卡片长标题、筛选面板所有关闭路径、跨月区间和年月跳转、番剧搜索键盘、照片预览手势的完整设备回归。
3. 大图备份的耗时、界面响应、实际峰值内存、存储空间不足与中断处理。
4. 应用进程被终止时的跨文件/元数据一致性；当前运行时失败回滚不等于持久事务。
5. 专用缩略图、残留文件清理和仅重试记录保存等后续优化。

## 6. 验收场景

以下是首版需要覆盖的验收场景。纯数据和模拟文件测试不能替代 Android/iOS 上的功能验收。

| 场景                                 | 预期结果                                                                     |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| 首次手动勾选某点位                   | 生成当天无图记录，只更新当前计划 check                                       |
| 同一天在另一计划勾选同一点位         | 复用当天记录，不重复生成；计划 check 各自独立                                |
| 取消勾选后同一天重新勾选             | 取消时保留历史，重新勾选复用当天记录且不改首次时间                           |
| 首次成功导出                         | 保存系统相册和应用成品副本，生成或复用当天记录，不修改计划 check             |
| 同一天多次成功导出                   | 每张成品各自保留，属于同一条每日记录                                         |
| 不同日期再次成功导出                 | 新增那一天的记录，保留之前的历史                                             |
| 导出未成功保存系统相册               | 不追加本次照片，不因此创建新记录                                             |
| 系统相册成功但专用相册分类失败       | 仍按成功导出记录处理                                                         |
| 系统相册成功但记录写入失败           | 分别报告相册成功和记录失败，不自动重复保存相册                               |
| 已有旧计划完成状态，启动或恢复旧备份 | 不扫描补录，不生成当天的新巡礼记录                                           |
| 删除一天记录或点位全部记录           | 清理对应应用内数据和照片，保留计划 check 和系统相册照片                      |
| 删除模式勾选照片或整天记录           | 可跨日混选；整天覆盖其照片，逐张选满仍保留当天记录，无图日期也可选           |
| 日期筛选后全选                       | 仅选择当前可见日期及其照片，不涉及筛选之外的历史                             |
| 取消删除模式或删除确认               | 退出模式清空勾选；只取消确认则保留勾选，未确认时不删除                       |
| 批量删除写入或文件清理失败           | 元数据失败保留选择且不删文件；元数据已提交则退出模式，单独提示文件清理失败   |
| 清除应用缓存                         | 巡礼记录及应用内成品副本保留                                                 |
| 查看总览与点位详情                   | 总览按点位和最近巡礼时间排序，详情按日期展示，包含无图记录                   |
| 按番剧、时间段筛选                   | 有图、无图记录均可命中；番剧和时间取交集，排序、数量及缩略图只使用命中的日期 |
| 搜索并选择番剧                       | 搜索保留其他已选项，多选后点确定才应用；全部番剧或取消最后一项可取消该条件   |
| 选择最近7天、最近30天、本月或今年    | 最近天数包含今天，本月和今年从月初或年初截止今天                             |
| 日历选择自定义范围                   | 无需输入日期；可跨月、快速跳转年月；同日可选且起止日均包含，未选完不能确定   |
| 修改筛选后关闭面板                   | 点关闭、下滑关闭和返回均保留上次应用条件，放弃本次草稿                       |
| 在一个面板重置后确定                 | 只清空当前面板的条件，另一个条件保持原样                                     |
| 清除筛选或筛选无匹配结果             | 清除同时重置番剧和时间；无匹配时仍可修改或清除条件                           |
| 从筛选列表进入详情后返回             | 详情沿用范围并可清除以查看全部历史，返回后总览筛选保持原样                   |
| 备份并在另一设备恢复巡礼记录         | 记录日期、时间和照片身份保留，图片可在应用内查看，不写入系统相册             |
| 仅恢复巡礼记录                       | 不改变计划 check，也不生成恢复当天的额外记录                                 |
| 恢复不含巡礼记录的旧 JSON            | 按原有类别恢复，保留已有巡礼记录和图片                                       |

纯数据归档、去重、删除范围和备份兼容适合轻量测试；相册权限、文件生命周期、图片预览、筛选交互和大图备份恢复需要设备验收。类型、lint 与格式检查不能替代这些设备验证。
